06layout_weight — equal & unequal space

android:layout_weight assigns importance for leftover space. Default weight is 0. Use weightSum on the parent when helpful.

  • Equal: set height 0dp (vertical) or width 0dp (horizontal), each weight 1.
  • Unequal: weights 2 and 1 with weightSum="3" → first gets ~2/3 of remaining space.
  • Views with weight 0 keep only their content size.
<LinearLayout
  android:layout_width="match_parent"
  android:layout_height="match_parent"
  android:weightSum="3"
  android:orientation="horizontal">
  <TextView android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Label 1"
    android:layout_weight="2"
    android:textSize="20sp" />
  <TextView android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Label2"
    android:layout_weight="1"
    android:textSize="20sp" />
</LinearLayout>
Nepal tipSplit a toolbar: college logo (weight 1) + “Semester VI” title (weight 2) in a horizontal LinearLayout.

AttributeRole

12AbsoluteLayout (deprecated)

Big idea: pin each child at exact x,y — like stickers on a poster. Looks fine on one phone size, then breaks on others. Deprecated — learn it for exams, never ship it.

Deprecated
A · (40,30)
B · (120,90)
layout_x / layout_y = fixed dp from top-left
<AbsoluteLayout
  android:layout_width="match_parent"
  android:layout_height="match_parent">
  <TextView android:text="Label 1"
    android:layout_x="100dp" android:layout_y="50dp" />
  <TextView android:text="Label 2"
    android:layout_x="150dp" android:layout_y="100dp" />
</AbsoluteLayout>
Viva: Deprecated API 3 — use Relative, Linear, or ConstraintLayout.

13ConstraintLayout (modern default)

Big idea: widgets are tied to the parent or to siblings with constraint lines (top / start / end / bottom) — not stacked blindly. One flat parent can replace many nested LinearLayouts.

Parent · ConstraintLayout
A · Child
B · Sibling
Constraints draw from Parent → Child (top, start, end, bottom)
app:layout_constraintTop_toTopOf="parent" app:layout_constraintStart_toStartOf="parent" app:layout_constraintEnd_toEndOf="parent" app:layout_constraintBottom_toBottomOf="parent"

In Android Studio, those dashed lines are the Constraint Editor. Click a side of the child, drag to parent (or sibling). Next slide lists the XML attribute names.

Layouts · ConstraintLayout

14ConstraintLayout — key attrs & XML

These attribute names match what you just saw on the live stage. Prefer start/end (RTL-safe) over left/right in new code.

  • layout_constraintTop_toTopOf / _toBottomOf
  • layout_constraintBottom_toTopOf / _toBottomOf
  • layout_constraintStart_toStartOf / _toEndOf
  • layout_constraintEnd_toEndOf / _toStartOf
  • Also Left/Right family (older samples)
vs RelativeRelative: place a whole view to the right of another. Constraint: pin any side to any side — e.g. top of B to bottom of A and start of B to end of A.
<androidx.constraintlayout.widget.ConstraintLayout
  xmlns:android="http://schemas.android.com/apk/res/android"
  xmlns:app="http://schemas.android.com/apk/res-auto"
  android:layout_width="match_parent"
  android:layout_height="match_parent">
  <TextView android:id="@+id/label1"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Label 1" android:textSize="20sp"
    app:layout_constraintTop_toTopOf="parent"
    app:layout_constraintStart_toStartOf="parent"/>
  <TextView android:id="@+id/label2"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Label 2" android:textSize="20sp"
    app:layout_constraintStart_toEndOf="@+id/label1"
    app:layout_constraintTop_toBottomOf="@+id/label1"/>
</androidx.constraintlayout.widget.ConstraintLayout>

24Listeners, registration, handlers

  • Event Listener — interface in View with one callback; framework calls it when the registered view is triggered.
  • Registration — attach handler to listener so it runs when the event fires.
  • Event Handler — the method that actually reacts (onClick, etc.).

Wrap

36Key takeaways

  • UI = hierarchy of View (widgets) and ViewGroup (layouts), usually declared in XML.
  • Linear = one direction + weights; Relative = sibling/parent rules; Table = rows/columns; Absolute = legacy; Constraint = modern flat power.
  • Widgets: TextView, EditText, Button, CheckBox, RadioGroup, Spinner.
  • Events: listener → registration → handler (onClick + Toast demo).
  • Resources: strings / string-arrays, colors, drawables, manifest icon.
