SET PROTOCOL

What exactly is SET?

  • SET stands for Secure Electronic Transaction.
  • It is a communication protocol designed for secure electronic payment transactions such as credit-card transactions.
  • It is an open encryption and cryptography-based protocol for securing transactions over a network.
  • It is not a payment system itself; it is a security protocol used to protect payment transactions.
  • Uses encryption and hashing to protect credit-card details.
Protocol ≠ moneySET is the security choreography, not the cash itself.
HISTORICAL CONTEXT

Why this idea mattered

The real-world problem

  • Early e-commerce needed customers to trust merchants they had never met.
  • Card details were moving across networks and multiple organizations.
  • Security had to answer four questions: Who are you? Who is the merchant? Can anyone read this? Was anything changed?

Historical fact

SET was developed in the 1990s with major payment-industry involvement, including Visa and Mastercard. It never became the everyday checkout experience used today, but its security ideas are excellent for learning authentication, certificates, encryption and payment privacy.

SET PROTOCOL

SET’s 4 security promises

🏪 1. Merchant Authentication

  • Helps prevent theft/fraud by checking the merchant.
  • Verifies relationships between merchants and financial institutions.
  • Uses X.509v3 certificates to establish trust.

💳 2. Cardholder Authentication

  • Checks whether the credit-card user is an authorized user.
  • Uses an X.509v3 certificate to verify the cardholder.

🤐 3. Message Confidentiality

  • Prevents unintended people from reading the transferred message.
  • Implemented using encryption.
  • Traditionally, DES is used for encryption in SET.

🛡️ 4. Message Integrity

  • Does not allow messages to be modified without detection.
  • Protects against unauthorized modification.
  • Uses mechanisms such as RSA digital signatures with SHA-1 and HMAC with SHA-1.

SET PROTOCOL

Phase 1 — Cardholder Registration

  • This is the initial step for cardholders.
  • The cardholder/agent sends a certificate-authentication request to the CA.
  • The CA replies with a registration form.
  • The form is completed and returned, together with the signing key the customer wants to register.
  • CA checks the credit card is valid.
  • CA releases a signature certificate for future use.
  • Credit-card details must be protected during these protocol steps.

SET PROTOCOL

Dual Signature — the privacy superpower

Order Information (OI)

  • Information meant for the merchant.
  • Example: item ordered, quantity, delivery/order details.
  • Merchant needs to know what to deliver.

Payment Information (PI)

  • Information meant for the bank/payment side.
  • Contains payment/card-related information.
  • The merchant does not need to know the customer’s card number.

Core idea: the bank does not need the customer’s order details, and the merchant does not need the customer’s credit-card details. The dual signature connects OI and PI while keeping them separate for privacy.

REAL CASE • HEARTLAND

2008: card data was stolen while it was moving

Heartland Payment Systems • 2008
130M+

credit/debit card records were alleged stolen across the wider hacking campaign.

  • Heartland disclosed malicious software inside its payment-processing environment.
  • Its SEC filing said attackers collected in-transit, unencrypted payment-card data during transaction authorization.
  • Affected data included card numbers, expiry dates and magnetic-stripe information.

Connect it to SET 🔗

SET idea: Message Confidentiality.

If valuable payment data travels in readable form, an attacker who reaches the right point in the network can turn “data in transit” into “data in pocket.”

Attacker: “Don’t mind me…”Network traffic: unfortunately, very mind-able. 😬

COMMON CONFUSIONS

Don’t lose marks here ⚠️

Wrong

  • “SET is a payment method like a card or wallet.”
  • “Authorization and capture are the same.”
  • “Merchant should receive all payment details.”
  • “Confidentiality and integrity mean the same thing.”

Correct

  • SET is a security protocol for electronic transactions.
  • Authorization checks/approves; capture completes collection/transfer.
  • Dual signature helps separate OI from PI.
  • Confidentiality = prevent reading; integrity = prevent/detect modification.
