6.9

Data Analytics for IoT

IoT analytics means collecting, cleaning, processing, visualizing, and interpreting data generated by IoT devices.

IoT data often comes as a time series, such as temperature every minute, GPS location every few seconds, or power consumption every hour.

Why it matters

  • Converts raw readings into useful information.
  • Detects abnormal events such as overheating or water leakage.
  • Supports automation, monitoring, and decision making.
  • Helps create dashboards, reports, alerts, and predictions.
6.9
Analytics Pipeline

From sensor reading to smart decision

1. SenseSensor collects physical data.
2. SendDevice sends data through MQTT, HTTP, Wi-Fi, LoRaWAN, or cellular.
3. StoreData is saved in cloud, database, or time-series storage.
4. AnalyzeSystem calculates trends, thresholds, patterns, or predictions.
5. ActDashboard, alert, report, or automatic control is triggered.
Raw data becomes valuable only when it leads to a clear action.
Analytics Types

Four common types of analytics

TypeQuestion answeredIoT example
DescriptiveWhat happened?Daily average temperature from a sensor.
DiagnosticWhy did it happen?Temperature increased because the cooling fan was off.
PredictiveWhat may happen next?Predicting machine failure from vibration changes.
PrescriptiveWhat action should be taken?Start irrigation when soil moisture is below a limit.

Software and Management Tools for IoT

IoT software is used to program devices, connect them to networks, process data, build dashboards, and manage devices remotely.

💻

Development

Arduino IDE, Python, Raspberry Pi tools, ESP32 tools, PlatformIO.

📡

Communication

📈

Visualization

Node-RED, Grafana, ThingsBoard, Blynk, ThingSpeak dashboards.

6.10
Tool Stack

Main tool categories

Device programming tools

  • Used to write and upload code to microcontrollers.
  • Examples: Arduino IDE, Thonny, VS Code, PlatformIO.

Data and server tools

  • Used to receive, store, and process IoT readings.
  • Examples: Node-RED, Mosquitto, MySQL, MongoDB, InfluxDB.

Cloud platform tools

  • Used for dashboards, device registration, and monitoring.
  • Examples: ThingsBoard, Arduino Cloud, AWS IoT, Firebase.

Security and management tools

  • Used for authentication, updates, logs, and device health.
  • Examples: certificates, API keys, policies, OTA tools.
Device Management

Managing IoT devices at scale

Register device Authenticate Configure Monitor health Update firmware Detect errors Log activity Deactivate safely

Small IoT project

Manual management may be enough for a few sensors and devices.

Real IoT system

Hundreds or thousands of devices need centralized monitoring, updates, security, and alerts.

6.11

Cloud Storage Models and Communication

IoT devices create continuous data. Cloud storage keeps that data available for dashboards, analytics, machine learning, reports, and future decisions.

🧊

Object Storage

Stores files, logs, images, backups, and raw IoT data with metadata.

🗄️

Database Storage

Stores structured or semi-structured readings for applications and dashboards.

⏱️

Time-Series Storage

Stores data linked with time, such as one reading per second or minute.

📁

File Storage

Stores shared files in folder-like structure for applications.

🧱

Block Storage

Used for virtual machines and high-performance systems.

🌊

Data Lake

Stores large raw data from many sources for big data analytics.

6.11
Communication

How IoT systems communicate

Device to Device

Devices communicate directly, such as a smart switch controlling a smart light.

Device to Gateway

Sensors send data to a local gateway, which forwards it to the Internet or cloud.

Device to Cloud

Device sends data directly to a cloud platform using the Internet.

Cloud to Device

Cloud sends commands back to the device, such as turning a motor on or off.

6.12

APIs in IoT

An API, or Application Programming Interface, is a set of rules that allows one software system to communicate with another.

In IoT, APIs connect devices, mobile apps, dashboards, databases, and cloud services.

🔌
6.12
API Types

Common API styles for IoT

REST API

Uses HTTP methods such as GET, POST, PUT, and DELETE. Common in web and mobile apps.

MQTT API

Uses publish-subscribe topics. Best for lightweight IoT messaging.

WebSocket API

Supports real-time two-way communication between client and server.

Example REST request GET /devices/101/temperature Example MQTT topics home/kitchen/temperature home/kitchen/light/control
API Security

APIs must be protected

🔑

Authentication

Verifies who or what is connecting.

🛂

Authorization

Controls what actions are allowed.

🔒

Encryption

Protects data during transmission.

🧯

Rate Limits

Reduces misuse and overload.

Because IoT APIs may control real devices, weak API security can create physical safety risks.

6.13

Cloud for IoT

Cloud for IoT means using cloud computing services to store, process, analyze, manage, and control IoT data and devices.

SensorsCollect data from the physical world.
DeviceESP32, Arduino, Raspberry Pi, or industrial controller.
GatewayCollects data and connects local network to cloud.
CloudStores, processes, analyzes, and secures data.
AppDashboard, mobile app, alert, or control panel.
6.13
Cloud Evaluation

Benefits and limitations

Benefits

  • Large storage and high processing power.
  • Remote monitoring from anywhere.
  • Easy dashboard, alert, and report generation.
  • Scalable for many devices and users.
  • Supports analytics and machine learning.

Limitations

  • Requires reliable Internet connection.
  • May add delay for time-critical control.
  • Data privacy and security must be planned.
  • Cost can increase with high data volume.
  • Edge or fog computing may be needed near devices.
6.14

Amazon Web Services for IoT

AWS IoT is a set of cloud services from Amazon for connecting, securing, managing, and analyzing IoT devices.

🧠

AWS IoT Core

Main service for connecting devices to AWS cloud.

📜

Thing Registry

Stores information about IoT devices, called things.

📨

Message Broker

Supports publish-subscribe communication between devices and apps.

🪞

Device Shadow

Stores the latest known device state for apps and services.

⚙️

Rules Engine

Filters, transforms, and routes messages to other AWS services.

🛡️

Security

Uses certificates, policies, and permissions for safe access.

6.14
AWS IoT Flow

Basic working of AWS IoT

RegisterCreate a thing and attach security credentials.
ConnectDevice connects securely to AWS IoT Core.
PublishDevice sends data to an MQTT topic.
ProcessRules Engine sends data to storage or other services.
RespondApplication sends alerts, dashboards, or commands.
Example: Temperature sensor → AWS IoT Core → Rules Engine → Database or alert → User dashboard
